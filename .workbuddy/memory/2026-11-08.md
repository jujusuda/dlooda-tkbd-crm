## 2026-11-08 晚 真正根治：「飞书更新网页仍是旧数据」(v38)
- **根因（致命坑）**：`data.js` 用**同步 `XMLHttpRequest`** 拉 `/api/data`。Cloudflare Pages 的 PWA 由 Service Worker 控制（`sw.js` 已 `clients.claim` 接管所有页面），而**受 SW 控制的页面无法使用同步 XHR**（SW 拦截 fetch 但只能用异步 `respondWith`，同步请求会失败/被丢弃）。→ KV 数据永远加载不到，页面始终用静态 Oct-13 兜底；且 `catch` 把 `__DATA_SRC` 设为 `static`，导致底部 `if(__DATA_SRC!=='kv') return` 直接废掉了自动刷新轮询。
- **修复（改走 SW 异步）**：`sw.js` 拦截 `js/real-data.js` 请求（`/\/js\/real-data\.js(\?|$)/`），用**异步 `fetch('/api/data')`** 改取 KV 最新数据返回给 `<script>` 标签（异步 fetch 在 SW 下正常工作），`<script>` 加载即同步拿到最新 `window.REAL_DATA`；KV 空/失败回退静态文件；localhost/127 跳过。→ `data.js` 删掉失效的同步 XHR 块，仅保留「异步 fetch + 150s 轮询」自动刷新（去掉 `__DATA_SRC` 守卫，首轮 `_lastHash=0` 不误刷）。`CACHE_VERSION` v37→**v38**。
- **自动生效**：`app.js` 已有 `controllerchange` 监听，新 SW 接管后自动 `location.reload()` 一次；部署后用户只需正常打开/刷新，至多一次自动重载即见当天数据（无需手动清缓存；顽固时可 `?reset=1`）。
- **通用铁律（写进 MEMORY 通用坑）**：在 PWA/受 SW 控制的页面，**绝不能用同步 XHR 拉实时数据**；实时数据应交给 SW 拦截对应请求用异步 fetch 提供，或页面用异步 fetch + 重载/sessionStorage。
