# 2026-11-08 Dlooda TKBD CRM 工作日志

## 主数据 KV 优先加载（治本，修复「飞书更新网页不更新」）— v37 / 待提交
- **问题根因**（用户 11-07 反馈）：网页主数据写死在仓库静态 `js/real-data.js`；「同步飞书」按钮只把数据写进 Cloudflare KV（`functions/api/sync.js` POST → `env.DATA.put('real-data.js', ...)`），**前端从不读 KV**，刷新仍读静态旧文件 → 飞书改了网页不变。
- **方案 A 落地**：
  1. 新增 `functions/api/data.js`：`onRequestGet` 从 `env.DATA` 读 `real-data.js` 内容返回（含 `window.REAL_DATA`/`REAL_DATA_STATS`），`Cache-Control: no-store`；KV 为空返回 404 兜底。
  2. `js/data.js` 顶部注入 KV 优先加载：在读取 `REAL_DATA` 之前，用**同步 XHR** 拉 `/api/data` 并 `(0,eval)` 间接 eval 覆盖 `window.REAL_DATA`（本地 localhost/127.0.0.1 跳过，避免阻塞与 SW 交互；拉取失败静默回退静态）。同时算数据指纹 `global.__DATA_HASH`。
  3. `js/data.js` 结尾加 150s 轮询：异步比对 KV 数据指纹，变化且无输入框聚焦时 `location.reload()` → 飞书同步后最多 2~3 分钟自动刷新。
  4. SW 本就**网络优先**，`/api/data` 每次取最新不被缓存（确认 sw.js fetch 策略）。
  5. 升 `sw.js` CACHE_VERSION v36 → **v37**（确保拿到新 data.js）。
- **闭环验证**：`app.js` 同步按钮成功后 `location.reload()`（800ms 延迟，此时 KV 已写完成）→ 重载时 data.js 拉 KV 最新 → 数据更新。
- ⚠️ 副作用：本地开发（localhost）仍用静态文件，所以本地预览看不到 KV 效果，需在 pages.dev 验证。
- ⚠️ 页面「上传 Excel」(localStorage `dlooda_uploaded_data`) 优先级仍高于 KV/静态，若用户曾上传会掩盖飞书更新 → 需清 localStorage 还原。
