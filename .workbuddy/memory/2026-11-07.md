# 2026-11-07 工作日志

## 用户疑问：飞书改了数据，网页(小程序)不更新

### 根因（已逐行核对代码确认）
- 网页主数据来自**仓库静态文件** `js/real-data.js`（`<script src>` → `window.REAL_DATA`）。dashboard/creator/roster 全部读这个。
- 「同步飞书」按钮 + 每5分钟自动同步 → `POST ./api/sync` → `functions/api/sync.js` → `syncFromFeishu()` 生成 real-data.js 内容并 `DATA.put('real-data.js', ...)` 写进 KV，返回 ok+reload。
- **但前端从不读 KV 的 real-data**（全项目 grep `DATA.get` 仅 roster.js/status.js/[[path]].js，无任何前端取数逻辑）。reload 后读的是仓库静态文件 → 永远旧数据。「KV 兜底」只适用于名单库 `roster-v1`，不适用主数据。
- 结论：按钮是"假同步"，真正的线上更新唯一路径仍是 本地 `server/_run_sync_once.js` 生成 js/real-data.js → commit+push → CF Pages 构建 → 升 sw CACHE_VERSION → 用户 Ctrl+F5。

### 待办（已向用户提议方案A治本）
- 方案A：前端加载时优先 fetch KV 的 real-data.js、静态文件兜底，让「同步飞书」/自动同步真正刷新页面（需新增取数端点 + 引导脚本，约 2~3 文件）。等待用户确认是否实施。
- 方案B（临时）：用户本机跑 `node server/_run_sync_once.js` 再 push（需飞书凭据，AI 无）。
